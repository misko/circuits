# v1.1 red-team — layout / thermal / power-integrity lens

Scope note: this is a low-power balanced-audio pod, not a switcher. There is no
switch node, no gate drive, and no power stage — so the classic "switch-node
pour area / gate-drive dress / thermal-via-vs-dissipation" checklist finds
nothing to grade, and I say so with numbers in the non-findings. The live
attack surface here is the NEW `layout:`/P-ADJ machinery added to source in the
v1.1 pass, measured against the sealed board. Everything below was pulled from
`04_kicad/crow_mic_pod.kicad_pcb` with pcbnew, not from the ADRs or the waiver
text. Sealed board unchanged: DRC/unconnected/parity = **0 / 0 / 0**
(`verification/drc.json`), `audit_board.py` = PASS (0 fails, 0 warns).

I re-verified the three P-ADJ waiver numbers first — they are honest. P-ADJ
computes max pad-to-pad span across every pad on the net; I reproduced exactly:
FB_A **12.96 mm** (R6.2/U1.2/R7.1), FB_B **15.23 mm** (R9.1/R8.2/U1.6), BZ_P
**16.05 mm** (BZ1.1/D3.1/D2.1/R12.2). The waiver's 13.0 / 15.2 / 16.1 match.
Then I went after what the pad-span number *doesn't* capture.

## Findings

**P2 — NEW. The P-ADJ waiver reasons from a straight-line pad-span, but the
physical inverting-node conductor is up to ~2× longer; the datasheet rule the
waiver waives is about that conductor, not the span.**
Evidence (routed length, pcbnew track sum):
- FB_A: span 12.96 mm → **routed 20.15 mm** (F.Cu 18.8 / B.Cu 1.3, 2 vias)
- FB_B: span 15.23 mm → **routed 28.97 mm** (F.Cu 29.0, 0 vias) — **+90 %**
- BZ_P: span 16.05 mm → **routed 20.70 mm** (F.Cu 20.7)

The waived rule (SBOS855E 8.4.1) is "keep the feedback network close to the
inverting input to **minimize parasitic C on that node**" — a property of the
copper that actually exists, which is the 29.0 mm FB_B trace, not the 15.2 mm
pad-span the waiver's arithmetic ("a ~13 mm 0.2 mm trace adds ~1 pF") is built
on. Worse, both feedback traces run on F.Cu, which carries its own solid GND
pour (F.Cu zone = 3249 mm²) coplanar to the trace *and* the B.Cu plane
(3853 mm²) beneath — so the summing node sees microstrip + coplanar C, not the
free-air estimate. For FB_B that is ~2 pF, not ~1 pF. This is the same
methodological blind spot in the P-ADJ gate itself: `policy_audit.py` measures
`max(hypot(pad,pad))`, a lower bound on the electrical length, so a net that
snakes can under-report (here it caught the span but the waiver then reasoned
from the under-reported figure). The engineering conclusion still survives —
with RF‖RG ≈ 6.7 kΩ (gain-3 stage, R7=20k/R6=10k) the node pole sits ~12 MHz
even at 2 pF, above the ~5.3 MHz closed-loop crossover (16 MHz GBW / noise-gain
3) — so it is audio-band-tolerable. But the *evidence of record* under-measures
the real node by up to 90 %, and the disposition should cite the routed length
(20 / 29 / 21 mm), not the pad-span, so a future re-route target is honest.

**P2 — NEW. The OPA1678 `layout:` adjacency block is factually wrong and
self-contradictory about C7 — a source-compliance defect introduced by the v1.1
pass.**
Evidence: the block states `"C6, C7 (0.1uF V+ bypass) hard against U1.8 (V+)"`.
But C7's value on the sealed board is **"10u 5V bulk"** (a 10 µF bulk cap on
net 5V), not a 0.1 µF bypass, and it sits **10.84 mm** from U1.8 (C7.1→U1.8),
nowhere near "hard against." Only C6 (100 n, C6.1→U1.8 = **3.32 mm**) is the
actual V+ bypass. The block's own `notes:` even say "Single 5V supply → one V+
bypass path per 8.4.2" — one path, contradicting the two-cap adjacency line
directly above it. This is not a board defect (the board's decoupling is
correct: one 100 n bypass local, one 10 µF bulk nearby) and it is graded HUMAN
(S7), so it does not trip a machine gate — but the whole point of the v1.1 pass
was source compliance, and this newly-authored `layout:` block mis-identifies a
part and asserts a placement the board neither has nor needs. Fix the block to
list C6 as the sole 0.1 µF V+ bypass and C7 as bulk.

**P2 — NEW (evidence provenance). The FB_A/FB_B waiver borrows a red-team
conclusion about a different net.**
Evidence: `policy_waivers.yaml` P-ADJ justifies FB_A/FB_B with "Matches red-team
L4 (op-amp C6-U1 loop, waived as audio-band-negligible)" and "independently
confirmed benign by the sealed release red-team review." But L4 (DISPOSITIONS.md)
is the **decoupling loop** C6→U1.8 = 3.3 mm — a different net (5V), a different
mechanism (supply bypass inductance), and a different measurement. The v1.0
red-team never measured or waived the FB_A/FB_B **feedback** spans; they are new
over-budgets surfaced only by the v1.1 P-ADJ gate. So "independently confirmed
by the red-team" overstates the pedigree — per this project's own canon
("a waiver copied from another finding is not a judgement"), the feedback-span
waiver stands on its own physics (which I re-derived above and accept), not on
L4. Re-word the `why:` to own that. The BZ_P→L2 cross-reference, by contrast,
is fair (same beeper loop, same net).

- **L5 (P2, OPEN).** The ADR-0004(c) first-article lid-close gate (J1 body

## Non-findings (so they aren't re-litigated)

- **Thermal / dissipation / thermal vias:** no power stage. Pod draw ≈ 6 mA;
  R1 (100 R, 5VF) dissipates ~3.6 mW worst-case; SS14 (D2) only passes the
  150 mA/4 kHz flyback pulse; PWR/BEEP copper is 0.4 mm floor (~1 A class,
  >6× margin). There is nothing for a thermal-via or ampacity finding to bite.
- **Plane / layer adjacency:** F.Cu (3249 mm²) and B.Cu (3853 mm²) both solid
  GND; every signal has a continuous reference on the opposite layer. The
  feedback-node concern above is coplanar-C, not a plane cut.
- **P-ADJ machine result:** passes only because all three keep_short nets are in
  the waiver; the waiver entries match the gate's own measurement exactly.

## Verdict: ORDER

Would I order THIS sealed board as-is: yes. Zero P0. The three new findings are
accuracy defects in the v1.1 *documentation* (routed-length vs pad-span in the
waiver evidence, the C7 adjacency mislabel, the L4 provenance overreach), not
electrical or manufacturing defects in the copper — the board is DRC/parity
clean and every electrical over-span is audio-band-tolerable at a ~5 MHz
crossover. The standing condition is unchanged from v1.0: the ADR-0004(c)
first-article lid-close gate (L5) must actually be run before the fleet is
built, since worst-case jack fit is −0.14 mm and no unit has been assembled yet.
