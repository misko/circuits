# CAL-1 re-derivation and the v1.4 feasibility determination

Commissioned as *"seal a v1.4 BOM-only supersede of v1.3 that fixes CAL-1
(R4 = 33 k / R5 = 18 k)"*, with two standing instructions: re-derive CAL-1
rather than take it on faith, and establish FIRST whether the change is
genuinely BOM-only — stopping if it is not.

**NO RELEASE WAS SEALED. Nothing under `07_releases/` or `04_kicad/` was
written.** Both instructions fired:

1. **CAL-1's DEFECT reproduces exactly. Its FIX does not.** The audit's
   stimulus (106.82 dB SPL), its load correction (+2.135 dB) and its v1.3
   ceiling column (106.81 / 103.81 / 101.31 dB) all re-derive to the second
   decimal. Its *fix* claim — "R4 = 33 k / R5 = 18 k clears the burst by
   3.4 dB worst-case" — reproduces **only** under an op-amp output-swing
   headroom of **0.100 V**, while the same review, eight paragraphs earlier,
   cites the datasheet's **0.800 V**. Under 0.800 V the proposed fix
   **still clips, by 1.65 dB worst-case**. The 3.4 dB is not a rounding
   difference; it is an 8× change of an unstated assumption, worth 4.5 dB.
2. **The change is NOT BOM-only, measured.** On this pipeline a resistor's
   VALUE is carried by the board and by the schematic, so it reaches
   `fab/cpl.csv`, `source/*.kicad_pcb`, `source/*.kicad_sch` and
   `source/*.net`. The commissioned copper-identity proof (`.kicad_pcb` md5
   unchanged **and** `fab/cpl.csv` byte-identical) is unsatisfiable by any
   honest execution of this change — the only way to hold both is to
   hand-edit the CSV, which canon M3 forbids.

The **copper genuinely does not move** — that part of the premise is true and
is measured below (11/11 gerbers+drills byte-identical). What is false is the
inference that "no copper" implies "BOM only".

### 1.1 The stimulus

```
LS1 (33.000, 46.000)   MK1 (74.000, 26.000)   |Δ| = 45.61798 mm
SPL = 100 dB @ 10 cm  +  20·log10(100.000 / 45.618)  =  106.817 dB SPL
```

Reproduces the audit's 106.8 dB. LS1's ≥100 dB @ 10 cm is the datasheet
MINIMUM, so this is a floor, not a typical.

### 1.2 The transfer function (re-derived from the .tsx, not quoted)

| node | derivation | value |
|---|---|---|
| stage A AC gain | `1 + R6/R7 = 1 + 10k/20k` | **1.500 V/V** |
| stage A DC gain | C4 blocks → OUTA = INP | 1.000 (OUTA sits at VMID) |
| stage B | `−R9/R8 = −10k/10k` on OUTA, +INB on VMID | **−1.000 V/V** |
| differential | OUTA − OUTB | **3.000 V/V** |
| VMID (v1.3) | `5.000 × 22k/(22k+22k)` | **2.5000 V** |

### 1.3 The microphone, at THIS board's operating point

AOM-5024 sensitivity −24 dB re 1 V/Pa = 63.10 mV/Pa, spec'd at **RL = 2.2 kΩ**
against a 2.2 kΩ source impedance. This board loads it with **R2 = 3.9 kΩ**:

```
correction = [3.9/(3.9+2.2)] ÷ [2.2/(2.2+2.2)] = 1.2787  →  +2.135 dB
S(board) = 80.68 mV/Pa
```

Reproduces the audit's +2.14 dB / 80.7 mV/Pa. **`part.yaml`'s headroom numbers
are optimistic by exactly this much** — confirmed.

### 1.4 The ceiling, and the three output-swing models in this tree

The binding limit is whichever of four constraints is smallest, expressed as a
peak signal at INP (`G = 1.5`, `Vm` = VMID, `h` = output headroom from either
rail):

```
in_cm_pos = (V+ − 2) − Vm       in_cm_neg = Vm − 0.5
out_neg   = (Vm − h) / G        out_pos   = ((V+ − h) − Vm) / G
SPL = 20·log10( (Vpk/S) / √2 / 20 µPa )
```

`VCM = (V−)+0.5 … (V+)−2` is read directly from SBOS855E §6.7, INPUT VOLTAGE
RANGE row — confirmed verbatim.

`h` is where the tree disagrees with itself. **Three different values are in
use and not one of them carries a citation to a load condition:**

| where | `h` | what it makes the fix look like |
|---|---|---|
| SBOS855E §6.7 `VO` row, and the front-page feature line — the only SOURCED number | **0.800 V** (MIN/MAX, at `RL = 2 kΩ`, `VS = ±15 V`) | fix still clips |
| `02_parts/OPA1678IDR/part.yaml` ("output clips at 1.53 Vpk") | **0.200 V** (implicit, unsourced) | fix clears by 2.9 dB |
| `2026-07-27_v1.3_adversarial-audit_first-principles.md`, fix paragraph | **0.100 V** (implicit, unsourced) | fix clears by 3.4 dB |

The audit's own text cites 0.800 V for the *ceiling* ("binds 2.3× before the
output swing does — (V−)+0.8 to (V+)−0.8, same table") and then computes the
*fix* with 0.100 V. Both are recoverable exactly from its published numbers:

```
audit fix, nominal: 113.7 dB → Vpk 1.1098 → OUTA swing 1.6647
                    → 1.7647 − 1.6647 = 0.1000 V headroom
audit fix, worst:   110.2 dB → Vpk 1.0510 → OUTA swing 1.5765
                    → 1.6765 − 1.5765 = 0.1000 V headroom
audit ceiling:      "2.3×" → (2.5 − 0.8)/1.5 ÷ 0.5 = 2.267 → 0.800 V headroom
```

150 mA burst — the same instant the SPL peaks).

|---|---|---|---|---|

### 1.6 Which `h` is defensible?

Neither extreme is free.

- **For 0.800 V:** it is the only number the datasheet guarantees. It is a
  MIN/MAX limit, and it is also what TI's own front page claims
  ("rail-to-rail output swing to within 800 mV with a 2-kΩ load").
- **For something much smaller:** the 0.800 V figure is tied to `RL = 2 kΩ`
  at `VS = ±15 V`, i.e. **≈7.1 mA** of output current. This board's AC load on
  OUTA is `(R6+R7) ∥ R8 ∥ (R10 + Z_cable_load)` = `30k ∥ 10k ∥ 10.1k` =
  **4.30 kΩ**, and at the v1.4 clip point that is **0.22 mA — 3.2 % of the
  spec's test current**. Figure 6-22 (Output Voltage vs Output Current) is
  monotonic in the helpful direction. The real part will swing far closer than
  800 mV; the datasheet simply does not promise it.

**The honest position: the fix's margin is somewhere between −1.7 dB and
+3.5 dB and the repo cannot presently say where, because no one has ever cited
an output-swing model to a load condition.** That is the finding. Note what it
implies for the *choice of values*, not just their sufficiency:

| `h` | best achievable worst-case ceiling, over ALL divider ratios | at VMID(5 V) | 33k/18k gives |
|---|---|---|---|
| 0.800 V | 107.67 dB (**+0.86 dB**) | 2.074 V (ratio 0.4148) | 105.17 dB (−1.65) |
| 0.200 V | 110.01 dB (+3.19 dB) | 1.821 V (ratio 0.3642) | 109.70 dB (+2.88) |
| 0.100 V | 110.34 dB (+3.52 dB) | 1.779 V (ratio 0.3558) | 110.27 dB (+3.45) |

So 33k/18k (ratio 0.3529) is **near-optimal if the light-load model holds** and
**materially sub-optimal if the datasheet limit is taken literally** — under
0.800 V no divider clears by more than 0.86 dB, and the optimum sits at a
*higher* VMID (≈2.07 V), the opposite direction from the proposed change.
**33k/18k is a strict improvement under every model** (+2.2 to +4.2 dB of
worst-case ceiling); it is simply not proven sufficient.

### 1.7 Arithmetic, verbatim (re-runnable)

```python
import math
LS1, MK1 = (33.0, 46.0), (74.0, 26.0)
D = math.hypot(LS1[0]-MK1[0], LS1[1]-MK1[1])            # 45.61798 mm
SPL_BURST = 100.0 + 20*math.log10(100.0/D)               # 106.817 dB
S = 10**(-24/20) * (3900/(3900+2200)) / (2200/(2200+2200))   # 0.08068 V/Pa
G = 1 + 10e3/20e3                                        # 1.5
def ceiling(vplus, r4, r5, h, s):
    vm = vplus*r5/(r4+r5)
    vpk = min((vplus-2.0)-vm, vm-0.5, (vm-h)/G, ((vplus-h)-vm)/G)
    return 20*math.log10((vpk/s)/math.sqrt(2)/20e-6)
worst = lambda r4, r5, h: ceiling(4.75, r4, r5, h, S*10**(3/20))
for h in (0.8, 0.2, 0.1):
    print(h, round(worst(22e3,22e3,h),2), round(worst(33e3,18e3,h),2))
# 0.8 101.31 105.17 | 0.2 101.31 109.70 | 0.1 101.31 110.27
```

## 2. Is it BOM-only? Measured — no

The premise given was: *R4 and R5 are existing placed resistors, so changing
their VALUES changes the BOM and nothing else.* The first half is true; the
second is not, and the mechanism is in the exporter.

`skills/jlcpcb-fab/scripts/export_jlc_package.py:349` reads
`val = fp.GetValue()` **from the board**, and that one string feeds BOTH the
BOM Comment (`groups.setdefault((code, val, fpname), …)`) **and the CPL**
(`cpl.append([ref, val, fpname, …])`, `Val` column). v1.3's shipped
`fab/cpl.csv` rows 21–22 literally read `R4,22kΩ,…` / `R5,22kΩ,…`.

**Experiment.** Two exports run from identical inputs, differing only in the
two `(property "Value" …)` strings inside the R4 and R5 footprint blocks —
a **4-line** diff in the `.kicad_pcb`, no copper token touched.
(`06_build/proof/vc_{base,mod}`, gitignored/disposable; both exports exited 0.)

| artifact | base → mod | verdict |
|---|---|---|
| **9 gerbers + 2 drills** | **11/11 byte-identical** after stripping the plot-timestamp lines | **copper, silk, mask, paste, drill: UNMOVED** |
| same 11 vs **sealed v1.3 zip** | **11/11 byte-identical** | the sealed fab set re-plots from its own source; the method is validated |
| `fab/cpl.csv` | **2 rows differ — the `Val` cells** (`22kΩ` → `33kΩ` / `18kΩ`); 0 coordinate, rotation, layer or package changes | **NOT byte-identical** |
| `fab/bom.csv` | the merged `22kΩ,"R4,R5"` row is REPLACED by `18kΩ / 33kΩ,"R4,R5"` — 1 row removed, 1 row added | a row ADDED and a row EDITED |
| `.kicad_pcb` md5 | `c7b8512c…` → `2e0c98bd…` | **NOT unchanged** |

And the board cannot be changed alone: the schematic carries the same value
(`source/crow_mic_pod_v2.kicad_sch:675,683` — `(property "Value" "22kΩ")`),
and the release gate checks it. Measured with `kicad-cli pcb drc
--severity-all --refill-zones --schematic-parity` on both boards against the
**sealed, unmodified** schematic:

```
base : 0 violations / 0 unconnected / 0 schematic parity issues
mod  : 0 violations / 0 unconnected / 2 schematic parity issues
       footprint_symbol_mismatch  "Value (R4) doesn't match symbol value (33kΩ)"
       footprint_symbol_mismatch  "Value (R5) doesn't match symbol value (18kΩ)"
```

(The base run is also an independent re-confirmation of v1.3's sealed
DRC 0/0/0 from the archive's own bytes.)

`source/crow_mic_pod_v2.net` likewise carries per-component values, so it moves
too. The schematic is generated by the tscircuit bridge, so the change starts
in the `.tsx` and re-runs `gen_tscircuit.sh` → `count_parity.py` → netlist
export → board regeneration — i.e. it is a **source revision**, and its release
would be a **source-differing, fab-differing supersede**.

Against the three supersede modes in `07_releases/contracts.md`:

| mode | requires | this change |
|---|---|---|
| `--docs-only-supersede` | `fab/` `source/` `3d/` byte-identical | FAILS (bom, cpl, 3 source files) |
| `--bom-only-supersede` | as docs-only **plus** the bom delta is whole rows **REMOVED**, for designators **NOT on the CPL** | FAILS on all four clauses — cpl.csv moves, source moves, a row is added, and R4/R5 **are** on the CPL |
| `--cpl-only-supersede` | everything but `fab/cpl.csv` identical; **"a `Val` … change FAILs"** | FAILS, and the `Val` change is named by that mode as its own exclusion |

There is no mode for this shape. The nearest precedent, `usb-hub-3s-v3` v1.11,
had it **easier** — it substituted an LCSC code at the same value, so
`fp.GetValue()` never moved and the board, CPL and schematic all stayed
byte-identical (its CHANGELOG records "0 Comment changes"). That precedent does
not transfer.

**Nothing here says the change is wrong. It says the change is not the cheap
shape it was authorized as, and that the copper-identity proof it was to be
sealed against cannot be produced.** The user authorized a BOM-only value
change; the honest execution is a source revision, so the decision returns to
the user.

## 5. Scope — POE-1 and PSR-1 are NOT addressed here and remain open P1s

Both need copper and were explicitly out of scope. Neither is fixed, mitigated
or downgraded by anything in this document. Recorded so they are not lost:

- **POE-1** — nothing clamps 48 V; RJ45 contacts 4/5 reach U1.8 with zero
  series impedance; D1 covers only contacts 1/2; the realistic carrier is a
  passive injector, not a compliant PSE; the residual-risk list omits the
  MLCC ignition path (C1 at 7.6× rating, then ~23 W in an 0603). ADR-0005's
  accepted waiver stands; its stated MECHANISM needs the correction.
- **PSR-1** — VMID gets ~0.2 dB of differential rejection (VMID→Vdiff 2.92 vs
  signal 2.97); 1 mV of 60 Hz on 5V_AUDIO ≡ a 34 dB SPL tone, coherent across
  all six pods; no ripple spec exists on the cable contract. The v1.4 divider
  change would drop the **VMID injection term** by 3.04 dB (above) but leaves
  the DOMINANT path — the 16 Hz R1·C1 mic-bias corner, −11.4 dB at 60 Hz —
  untouched, and the two paths partially cancel, so the net effect is within a
  few tenths of a dB in an unknown direction. **PSR-1 is not resolved by CAL-1's
  fix and must not be recorded as such.**
