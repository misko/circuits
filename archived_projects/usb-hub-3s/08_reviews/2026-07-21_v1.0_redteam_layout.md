# Red-team B: adversarial power-stage / PI layout review — usb-hub-3s v1.0-2026-07-21

Reviewer lens: power-stage layout, thermal, power integrity. All numbers measured with
`/usr/bin/python3` + pcbnew against the SEALED board
`07_releases/v1.0-2026-07-21/source/usb_hub_3s.kicad_pcb` (zone fills read from the file's
saved polygons via `GetFilledPolysList`; distances from pad/via/track coordinates; BOM from
`07_releases/.../fab/bom.csv`). Board: 110×82mm, 4-layer F.Cu / In1(GND) / In2(VIN) / B.Cu.
No stackup section in the file (grep "stackup" = 0 hits) → JLC 4-layer default assumed:
1oz outers, 0.5oz inners, ~0.21mm outer-to-inner prepreg. Coupling/ampacity numbers below
use that; if a different stackup was ordered the numbers move but not the conclusions.

Topology recap (from netlist): IP6559 4-switch buck-boost — input half-bridge Q4(HS,
D=VIN_S)/Q5(LS, D=LX2), output half-bridge Q6(HS, D=VOUT_PDS)/Q7(LS, D=LX1), L1 between
LX1/LX2; input shunt RS2 (VIN→VIN_S, 5mΩ), output shunt RS3 (VOUT_PDS→VOUT_PD, 5mΩ).
LM5116 buck: Q2(HS)/Q3(LS), low-side shunt RS1 (10mΩ), L2 → 5VA.

## P0 findings

### P0-1: PD converter has ZERO high-frequency decoupling on either bridge rail; both hot loops are 50–63mm perimeter with a 5mΩ shunt inside
Measured pad-net map: net **VIN_S** contains ONLY {Q4.5 drain, RS2.2, R15.1, U1.24} — **no
capacitor of any kind**. Net **VOUT_PDS** contains ONLY {Q6.5 drain, RS3.1, R18.1, U1.15} —
**no capacitor**. The nearest input-loop ceramics sit on VIN *behind* the shunt: C3 (one
10µF 1210, pad at 88.5,62.0) and C4 (100nF). Measured loop legs (pad center to pad center):

- Input loop (buck-mode / hard edges): C3.1→RS2.1 = 4.0mm; through shunt 5.9mm;
  RS2.2→Q4 drain = 6.6mm; Q4 source→Q5 drain (LX2) = 12.5mm; Q5 source GND→C3 GND
  = **33.7mm**. Perimeter ≈ **63mm**.
- Output loop (boost-mode / hard edges): Q6 drain→RS3.1 = 11.3mm; through shunt 5.9mm;
  RS3.2→C27 (the only ceramic, a single 100nF 0603) = 6.9mm; C27 GND→Q7 source GND =
  **19.6mm**. Perimeter ≈ **44mm**, and the only bulk is one polymer electrolytic C26
  (high ESL) 10.2mm from the shunt. DETAIL_DESIGN §5 itself specifies "2×10µF 25V ceramic"
  input ceramics — the BOM has **one** (C3), and it is 13mm of copper away from Q4 with the
  shunt in between.

Consequences at the 100W corner (9V in, 20V/5A out, ~12A inductor current): tens of nH of
loop inductance where reference practice is <3nH; LX ringing that the parts cannot absorb —
the FETs (AON6354) are **30V abs max / 36V 10µs spike**, the bus is 20V, and the fitted
"protection" TVS (SMAJ30A, D6/D7) has Vwm=30V and **clamps at ~48V** — i.e. it clamps only
after the FET is dead. The 2Ω/1nF snubbers are the sole real damping on a 63mm loop.
Overshoot of 25–50% (typical for this loop class) puts Vds at 25–30V+ → at/over abs max at
every 20V-mode edge. This is a blow-a-FET-at-the-corner defect, not a cosmetic one.

**Correction (placement-level, mandatory):** put 2×10µF+100nF X7R directly across
VIN_S–GND at Q4/Q5 (inside ~3mm), and 2×10µF 25V+100nF across VOUT_PDS–GND at Q6/Q7;
pull Q5 next to Q4 and Q7 next to Q6 (HS-source-to-LS-drain 1–2mm, currently 12.5mm and
10.1mm). Keep the shunts OUT of the HF loop (ceramics on both sides of each shunt).

### P0-2 (P0 by consequence, sense-domain): neither PD current sense is Kelvin — both taps read shunt + long stretches of current-carrying copper
DETAIL_DESIGN §5 promises "PCIN/PCON direct taps at the shunt outer ends (DS §13.5 Kelvin
rule)". Measured:

- **Input sense**: SNS_IN_P filter R14.1 taps net VIN at (75.2,63.0) via two vias into the
  In2 plane — **10.9mm from shunt pad RS2.1 (86.0,65.0)**. The full ~12A PD input current
  reaches RS2.1 through that same plane and its 3 exit vias ((86.0,65.0),(88.5,62.0),
  (89.2,65.0), all 0.15mm drill ≈2.9mΩ barrel each). ≥1mΩ of via+plane resistance is
  inside the sense path → ~12mV parasitic on a 60mV full-scale (12A×5mΩ) signal =
  **~20% over-read of input current**, drifting with copper tempco (+0.39%/°C vs the
  100ppm alloy shunt the BOM paid for). SNS_IN_N (R15.1 at 80.05,68.2) taps the VIN_S pour
  6.5mm from RS2.2, also off-pad.
- **Output sense**: SNS_OUT_P filter R18.1 taps VOUT_PDS at (66.2,68.9) — **~14mm of
  current-carrying finger away from shunt pad RS3.1 (52.5,85.0)**; the VOUT_PDS finger
  (3.6mm wide F.Cu, 47.8mm² + 39.1mm² B.Cu) carries the full output current, adding
  ~0.8–1.6mΩ → 4–8mV on a 25mV (5A) signal = **16–30% over-read**. SNS_OUT_N (R19.1 at
  63.0,65.8) taps VOUT_PD **27.3mm** from RS3.2.

Effect: the IP6559's constant-current loops (input CC and the PD-advertised output limits)
run 15–30% early and temperature-dependent → the board cannot deliver its rated PDOs at
the low-Vin corner, and the limits wander with load-induced heating.

**Correction (route-level, but requires P0-1's placement fix to be clean):** route each
sense pair as a true differential pair from dedicated tap stubs on the shunt pads
themselves (tracks leaving the pad ends, no shared copper with the current path), length ≤
a few mm to the R-C filters, filters next to U1.

## P1 findings

### P1-1: 400mm² switch-node copper per node, half of it a dead stub facing the VIN plane
Measured filled areas: **LX1 = 196.7mm² (F.Cu) + 225.9mm² (B.Cu) = 422.6mm²**;
**LX2 = 170.8 + 191.7 + 35.5 = 398.0mm²**; strips run y=68.5→104 (35.5mm) because L1 was
placed 13.0–23.1mm from the FETs (measured Q7.D→L1.LX1 = 13.0mm, Q4.S→L1.LX2 = 23.1mm).
The In2 **VIN plane is fully present underneath** (measured overlap: 242.7mm² under the
LX1 strip, 193.4mm² under LX2). The B.Cu LX strips face that plane across ~0.21mm prepreg:
≈0.17pF/mm² → **~39pF per node** injecting C·dv/dt ≈ 50–80mA pulses (20V, ~5ns edges)
directly into the input rail plane, bypassing all input filtering, straight out the battery
leads. Worse: the B.Cu strips are connected to F.Cu only at their north ends (measured:
**zero LX1/LX2 vias south of y=88**; L1's pads are F.Cu-only SMD) — they carry no current;
they are pure parasitic aggressor area. This directly violates the project's own canon
(DETAIL §6: SWITCH_NODE "poured islands, minimal area").

**Correction:** move L1 up against the FET row (placement); delete the B.Cu LX strips
entirely; shrink F.Cu LX islands to FET-pads + L pad + snubber/TVS/BST landings
(~40–60mm² each). If B.Cu copper is kept for thermal, cut the In2 VIN plane under it.

### P1-2: SNS_OUT differential pair threads THROUGH the LX1 switch-node copper at 0.25mm
Measured minimum edge distances from sense tracks to the LX1 filled polygon:
SNS_OUT_N F.Cu segments at (60.9–62.4, 70.5–72.4): **0.25mm** from LX1 fill for ~3.5mm of
run; SNS_OUT_P B.Cu segments: **0.25mm**. A 20V/ns-class aggressor 0.25mm from the 5mΩ
sense lines on both outer layers. The 10Ω/1µF filter (C25 — itself placed inside this
corridor at 62.5,71.5) suppresses most of it above ~16kHz, but rectified HF on a 25–60mV
signal is a classic CC-instability mechanism. Route the pair east of U1, away from the LX
corridor (falls out naturally once P0-1/P1-1 shrink the geometry).

### P1-3: the 16A battery trunk crosses layers through five 0.15mm-drill vias, on a plane with THERMAL relief connections
Measured: no F.Cu continuity between the west VIN zone and the PD/buck VIN zones — the
trunk rides the 0.5oz In2 plane, entering through **5 vias** (41.7,79.4)(41.7,81.9)
(44.3,72.5)(44.8,80.5)(50.2,67.5), all 0.35mm pad / **0.15mm drill** (~2.9mΩ barrel each),
and exiting to the PD stage through **3** more (4A/via at 12A). Both inner planes are set
to **thermal-relief connect (spoke 0.5mm / gap 0.5mm)** — read from the zone objects
(`GetPadConnection()=THERMAL`) — so each 3A+ via hangs on four 0.5mm×0.5oz spokes.
Resistively survivable (~0.6mΩ per cluster, ~30mV total), but 3.2A through a 0.15mm drill
is 2–3× above any conservative ampacity guidance and a thermal-cycling reliability defect.
**Correction:** solid (full) connect for vias on the In1/In2 planes; 0.45mm-drill via
farms (≥8 per transition) at trunk entry/exit; ideally add a parallel F.Cu/B.Cu trunk.

### P1-4: "thermal vias" are 2×0.15mm-drill per power FET ≈ 218 K/W — token R-THERM compliance
Measured via census inside each drain-paddle bbox: **Q1: 2, Q3: 2, Q4: 2, Q5: 2, Q6: 2,
Q7: 2, Q8: 2, Q2: 0, L1 pads: 0, L2: 1**. A 0.15mm-drill/1.6mm via with ~20µm wall is
~437 K/W → two in parallel ≈ 218 K/W: the B.Cu landing zones the floorplan reserves
(e.g. LX2 B.Cu 35.5mm², VOUT_PDS 12.0mm²) are thermally unreachable. Dissipation at the
9V/100W corner (AON6354 Rds 3.3mΩ max @10V): Q4 conduction ≈ 12²×3.3mΩ = 0.48W; Q7 ≈
0.26W conduction + 0.5–1.5W hard-switching at 20V/12A/250kHz; Q1 (AON6403, 3.1mΩ) ≈
0.74W; L1 DCR ≈ 1.2–1.4W; RS2 = 0.72W on its 2512. Each FET then leans almost entirely on
F.Cu spreading (θ ≈ 40–50 K/W) → 40–70°C rises in still air, worse boxed. There is no
board-level thermal sensing (NTC slot R7/GPIO0 deliberately DNP per ADR-0004); the only
protection is the IP6559's internal 150°C OTP, which senses the QFN die — not the FETs
8–15mm away, not L1, not RS2. (U1/U2 exposed pads are fine: footprint-embedded via arrays,
25×0.2mm and 15×0.3mm, measured.) **Correction:** 5×5 arrays of 0.3–0.45mm drill vias in
every drain paddle and both L1 pads, solid-connected B.Cu spreaders (with P1-1's plane cut).

### P1-5: promised gate-resistor provisions do not exist
DETAIL_DESIGN §5: "Gate R 0Ω 0603 × 4 (tuning slots per DS Fig.7) reserved footprints."
Measured: nets HG1/HG2/LG1/LG2 each contain exactly two pads (U1 pin ↔ FET gate pad);
no resistor footprints exist on any PD gate (BOM confirms; the only 0Ω parts, R7/R8, are
the LM5116 CS filter). Gate route lengths: HG1 10.5mm, HG2 11.7mm, LG1 16.9mm, **LG2
21.2mm** at 0.2–0.3mm width with 2 layer changes. With P0-1's ringing there is no tuning
knob at all — every edge-rate fix becomes a mod-wire. **Correction:** restore the four
0603 slots at the chip end of each gate route (route-level; trivial after re-placement).

## P2 findings

- **Buck hot loop stretched to ~45mm**: Cin ceramics are well-placed at the HS drain (C9
  GND→Q2 drain = 4.6mm, C8 = 5.2mm) but the return runs Q3 source→RS1→RS1.2 GND (68,46.0),
  **21.9mm** from the nearest input-cap ground (C9.2 at 70.3,24.2). Low-side-shunt
  topology forces the shunt into the loop, but TI's own LM5116 layouts close cap-ground to
  shunt-ground in ~3mm. Mitigated by the solid In1 plane 0.21mm below; still 3–4× the
  reference loop. Fix by rotating RS1 up beside Q3 and pulling a Cin GND pad adjacent.
- **LM5116 CS taps only approximately Kelvin**: R7.1 taps the CS_A pour at (62.2,41.0),
  5.8mm west of shunt pad RS1.1 (68.0,40.0) — acceptably off the current path; the CSG
  side taps the GND pour ~5mm from RS1.2 through return-current-carrying copper.
  Few-percent error on the 10mΩ sense; acceptable for a current-mode ramp, sloppy for the
  11A current limit.
- **LX2 F.Cu strip ampacity at the corner**: 170.8mm² fill over 35.5mm ⇒ ~4.8mm average
  width of 1oz copper carrying ~12A average in boost ⇒ IPC-2152 ≈ **+29°C** self-heating
  along the strip (B.Cu strip contributes nothing — no south vias). Fixed for free by
  moving L1 (P1-1).
- **Doc/board drift**: DETAIL §5 says input stage gets "100µF ≥35V electro" at the stage —
  the two polymers C1/C2 sit at x≈47, 33–35mm from Q4, on the far side of the plane trunk;
  DETAIL's "2×10µF" is one 10µF on the board. Each drift is individually arguable;
  together they mean the released board does not implement its own §5 BOM intent.

## P3 notes

- VBAT pre-fuse trunk is F.Cu-only (325.1mm², ~11.5mm wide, 1oz): ~1.1mΩ, fine at 16A,
  survives fault-until-fuse-clear on thermal mass; would still prefer a B.Cu shadow.
- DPC/DMC to J5 measure 76.4mm vs 91.3mm (**15mm intra-pair skew**, 0.2mm width) — only
  BC1.2/Apple divider emulation lives on these (no HS data), so cosmetic here; would be a
  real defect on any board where DPC/DMC carried 480Mbps.
- Things that measured CLEAN, for fairness: snubber networks (R16/R17 2Ω + C23/C24 1nF)
  and BST caps (C21/C22) land correctly in the LX patches; buck input ceramics tight to
  Q2; In1 GND plane effectively solid (9358 of ~9900mm²); 171 GND vias overall, 8 in the
  PD low-side source region; U1/U2 EP via arrays present; VBUSC (684.5mm² F.Cu, ~8mm
  effective width) and 5VA (461+585mm²) pours comfortably carry 5A/7A; fuse-holder THT
  pads bond F/B VBAT_F copper.

## Verdict

**No — I would not run this board at full rated power as laid out.** At 5V/low-power PD
and the USB-A rail it will likely work (the LM5116 side is merely un-pretty). At the
100W corners (9V-in boost to 20V, or 20V hard-switching in buck mode) the PD power stage
combines: no HF decoupling on either bridge rail (P0-1), 44–63mm hot loops, 30V-abs-max
FETs on a 20V bus with a TVS that clamps at 48V, and current sensing that over-reads
15–30% (P0-2). Expected field behavior: early CC folding at best; FET avalanche/failure
at the 20V corner at worst; and it will not pass conducted EMI with ~80pF of switch node
strapped to the input plane (P1-1).

**Minimum re-layout scope** (this is a placement problem, not a routing problem — the
PD power stage must be re-floorplanned; the rest of the board can stand):
1. Re-place the PD stage as two tight half-bridges (HS/LS 1–2mm), L1 directly between
   them, input/output X7R ceramic banks inside each loop, shunts Kelvin-stubbed —
   roughly the region x=50–90, y=60–100 only.
2. Delete B.Cu LX strips; shrink LX islands to ~50mm²; cut In2 under any remaining
   switch-node copper.
3. Re-route both sense pairs as short true diff pairs off the shunt pads; add the four
   gate-R footprints.
4. Via program: 0.3–0.45mm drill thermal arrays under all drain paddles + L1; ≥8×0.45mm
   via farms at the In2 trunk entry/exit; solid-connect vias on both inner planes.
5. Re-verify: bench Vds overshoot at 20V/5A before any sustained 100W run, and re-check
   the input-CC/output-CC set points against a load bank (they are currently
   copper-defined, not shunt-defined).
