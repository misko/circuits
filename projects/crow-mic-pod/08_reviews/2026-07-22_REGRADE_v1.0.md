## Tooling finding (not a board defect): E-ADR's title regex is blind to this project's ADR filenames

`electrical_invariants.py`'s `_adr_title()` matches only headers of the form
`# NNNN — title` (e.g. usb-hub-3s's `# 0001 — Battery/input protection...`).
crow-mic-pod's ADRs (and crow-recorder-central's) are titled
`# ADR-NNNN — title` (e.g. `# ADR-0001 — input protection for a
5V-over-Cat5e outdoor pod (MANDATORY ADR)`). The regex requires four digits
immediately after `#\s*`; `ADR-0001` fails that match, so
`protection_adrs()` returns `[]` for this project **regardless of whether
`electrical_invariants.yaml` exists or what it contains** — verified directly:

    $ python3 -c "...ei.protection_adrs(Path('projects/crow-mic-pod/01_docs/decisions'))"
    []

E-ADR would report "OK" even with `electrical_invariants.yaml` deleted
entirely. This is a **false-PASS gate** — the exact failure mode CLAUDE.md
warns about ("a gate that cannot fail is worthless"). It does not invalidate
today's E-INV result (that check loads the file directly and is unaffected),
but it means E-ADR's "loop-closed" claim has not actually been machine-verified
here. Filed as a spawned background task (see report footer) rather than
patched in this session, since the script is shared repo tooling, not a
crow-mic-pod artifact, and touching it should carry its own test (a
known-bad fixture using `# ADR-NNNN` headers, per CLAUDE.md's checker-testing
rule) rather than a quick inline edit.

# 2. E-TOPO — N-A, by design (no converter on this board)

crow-mic-pod is a 2-layer, unpowered-logic (no MCU) analog pod fed 5V
directly over the Cat5e cable from the central board; it performs no
step-up/step-down conversion. Confirmed two ways:
1. `02_parts/` has no buck/boost/LDO controller part — the only active
   silicon is `OPA1678IDR` (op-amp).
2. ADR-0001's own UVLO section: "The pod is unpowered-logic (no MCU, no
   battery): no UVLO/OV circuitry is applicable... the GST25A05 source and
   the central board own rail quality" — i.e. the 5V/5VF rails are resistor-
   divided bias nodes (R1 100R + C1), not converter outputs.

No `03_src/rules/power_tree.yaml` was created — there is no rail here whose
topology (buck/boost/buck_boost) needs deriving. `policy_audit` correctly
reports `E-TOPO: N-A`.
