**CONSOLIDATED VERDICT: DO NOT ORDER — 3 P0 blockers.**
Lens verdicts: topology **DO NOT ORDER**; layout **DO NOT ORDER** (assembly); pin **FAIL (J1)**;
render/twin **HOLD (BOM)**. The board is DRC 0/0/0 / parity 0 and the *documented* pinout +
gain topology are internally correct — the blockers are protection, a footprint-mirror
correctness question, and an assembly-file DNP defect.

Severity | ID | Finding (lens) | Disposition
---|---|---|---
**P0** | A | **PoE Alternative-B power injection destroys U1.** 5V_AUDIO is ONE net = {J1.4, J1.5, U1.8 (V+), R1, R4, C7-C10} — zero series impedance between RJ45 contacts 4/5 and the op-amp V+. PoE 802.3af/at Alt-B (+V on 4,5 / −V on 7,8) aliases EXACTLY onto this board's 5V_AUDIO/GND. A PoE switch drives U1 V+ to 44-57V > OPA1678 abs-max `vs_max=40V`. (topology #1) | **ACCEPT-AND-FIX — USER DIRECTIVE-DECISION.** VERIFIED against netlist + part.yaml. Root: the RJ45-everywhere directive (ADR-0003) + protection-delegation (ADR-0001); ADR-0003's hazard analysis covered PHY-signal + backfeed but NEVER power injection. Fix is a PoE-defeat network (clamp <40V + PPTC fuse on 5V_AUDIO, or break the PoE-alias by moving 5V_AUDIO off 4/5/7/8) + re-layout, OR explicit user sign-off that the risk is accepted for this deployment. **Not auto-fixed** (directive tension — the user's call). SEAL-BLOCKER.
**P0** | B | **PoE Mode-A sustained conduction frets D1.** Mode-A (+V on 1,2 / −V on 3,6) forces the TPD2E2U06 (pulse-rated only) into continuous conduction — ≈(48−9.7)×0.35A ≈ 13W into a <2mm SOT-553 → thermal failure/burn hazard in an outdoor enclosure. (topology #2) | **ACCEPT-AND-FIX** — same PoE-defeat fix as A resolves it. Secondary path of the same root cause.
**P0** | C | **J1 RJHSE-5384 footprint may be a full contact MIRROR.** The stock KiCad `RJ45_Amphenol_RJHSE538X` LED-hole numbering is REVERSED vs the Amphenol dwg P-RJHSE-538X Rev K "RECOMMENDED P.C.B. LAYOUT (COMPONENT SIDE)": datasheet LED row = `12 11 … 10 9` (11,12 LEFT / 9,10 RIGHT); the KiCad footprint places 9,10 LEFT / 11,12 RIGHT. Both are component-side views, so a reversal implies a full 1↔8 contact mirror — which would swap EVERY custom-pinout net onto the wrong physical contact (field hazard). (pin FAIL) | **ACCEPT-AND-FIX → REQUIRED PHYSICAL-CONTINUITY CHECK BEFORE ORDER.** The LED-numbering reversal is CONFIRMED against the datasheet (orchestrator re-read); the contact mapping CANNOT be certified from the 2D drawing alone (the layout figure does not label contacts 1-8, and I have no part/STEP to probe). Before ordering, multimeter pad-1 copper → the physical contact-1 blade on a real RJHSE-5384 (the exact continuity discipline the design already prescribes for the LED-polarity ambiguity + the first-power ritual). If mirrored, vendor a corrected footprint. SEAL-BLOCKER until verified.
**P0** | D | **D3 (DNP) BOM/CPL/DNP inconsistency — assembly-file defect.** D3 is in `bom_jlc.csv` with a real code (C559105) but ABSENT from `cpl_jlc.csv`, with NO machine-readable DNP marker (`dnp no` on symbol; footprint has `exclude_from_pos_files` only). A BOM line with no CPL placement → JLC validator bounce or bill-but-never-place. (layout P0 / render P1 / topology P2) | **ACCEPT-AND-FIX (data-hygiene, path pending coordinator go).** RE-ADJUDICATED honestly — my earlier "handled on parity grounds" did NOT address the assembly-order consequence. EVIDENCE from a live test: setting D3's footprint value to `…DNP` DOES drop it from BOTH BOM+CPL, but `--schematic-parity` **checks value** and flags a mismatch unless the SYMBOL value also carries "DNP" — which the tscircuit converter cannot emit (it hardcodes symbol `in_bom=yes/dnp=no` and derives value from the supplier code). So a parity-clean end-to-end DNP needs EITHER (a) a converter enhancement to emit `dnp`/`in_bom`/value-with-DNP from source, OR (b) POPULATE D3 (parity-clean, +~$0.05 extended-tier, and electrically fine — SS14 flyback + SMAJ6.0A over-clamp don't conflict), amending ADR-0001. BOM-without-CPL is NOT a proven-clean JLC path (no evidence found; JLC's DNP mechanism is "DNP in value → out of both"). Recommend (b) populate-D3 as the clean minimal-risk resolution, or (a) for a future converter capability. NO auto-apply — awaiting path decision.
